O que é arquitetura de software? 
    A arquitetura de software envolve a definição de estruturas de alto nível de um sistema, seus componentes e a forma como interagem.

Definição - Conjunto de decisões significativas sobrre a organização de sistemas. 

A arquitetura é a base para o desenvolvimento decisões inicias impactam todo o ciclo de vida
    -> Impacto da qualidade - Desempenho, segurança, e etc...
    -> Comunicação - Guia da equipe técnica 
    -> Exemplo - Uma API mal estruturada, pode trazer problemas quando o sistema cresce 

Analogia - Uma estrada mal planejada cria engarrafamento, um sistma mal arquitetado cria gargalo

Atributos Essenciais 
    -> São caracteristicas que influenciam diretamente a qualidade do software

FORMATIVA 1 - PESQUISA EXPLORATÓRIA DE UM CRUD + AUTENTICAÇÃO

    Qual o padrão estrutural mais se encaixa com esse sistema? 
        
        -> Monolito Modular (Complexidade Baixa/Média)
            Roda em um único servidor node.js
            Pasta isoladas ou módulos estritamente separados 
            O módulo CRUD nunca interage com o banco de dados de usuários diretamente.
    
    Como funciona?
        -> Um middleware de autenticação intercepta a rota do CRUD, verifica o token JWT e injeta os dados do usuário na requisição (ex: req.user). O controlador do CRUD apenas confia nessa informação e executa a lógica de negócio.

            (O middleware é uma camada de software que funciona como uma ponte de comunicação entre diferentes aplicativos, sistemas operacionais ou bancos de dados.)
    
    Uso ideal
        -> Projetos acadêmicos, startups, facilidade de deploy.

    Pontos positivos
        -> Deploy Simples: Apenas um servidor, um repositório, e um ambiente somente 
        -> Comunicação: Auth e CRUD diretamente na memória do servidor, sem latência de rede
        -> Manutenção: Códigos no mesmo lugar, na hora de mudar uma regra ou interface é bem mais fácil
    
    Pontos negativos
        -> Risco de aclopamento: Sem diciplina na hora de codificar, limites lógicos são quebrados facilmente e o sistema vira um código espaguete.
        -> Escala engessada: CRUD com muito tráfego, você precisa alocar recursos para escalar a aplicação inteira


==========================================================================================================================

        -> Microsserviço (Complexidade Alta)
            Dois servidores node.js que rodam em portas diferentes
            Geralmente em Bancos de dados separados 

    Como funciona?
        -> Um serviço "Auth API" é o único dono da gestão de identidade. Ele cadastra, autentica e emite o JWT. O segundo serviço "CRUD API" apenas verifica a assinatura criptográfica do token recebido do cliente e executa as ações de domínio, sem nunca saber como a senha foi validada.

    Uso ideal
        -> Sistemas de escala massiva, regras de negócio complexas, times divididos.

    Pontos positivos 
        -> Limites invioláveis: É impossível misturar o código por acidente, pois eles rodam em servidores físicos ou virtuais completamente separados.
        -> Escala independente: Você pode adicionar mais processamento apenas para a API de CRUD, sem tocar na API de Auth.
        -> Resiliência: Se o serviço de CRUD travar devido a um erro, o serviço de Autenticação continua funcionando perfeitamente.
        -> Complexidade de infraestrutura (Negativo): Exige orquestração de containers (como Docker/Kubernetes), múltiplos pipelines de deploy e monitoramento distribuído.
    
    Pontos negativos 
        -> Latência de rede (Negativo): Os serviços precisam conversar entre si via HTTP ou filas de mensageria, o que adiciona tempo de resposta a cada requisição cruzada.
        -> Transações complexas (Negativo): Manter a consistência de dados entre dois bancos separados é uma das tarefas mais difíceis da engenharia de software.

Comparação direta

    Característica            Monolito Modular                         Microsserviços
    Comunicação interna       Chamadas de função na memória (Rápida) | Chamadas de rede HTTP/Eventos (Com latência)
    Implantação (Deploy)      Única e direta                         | Múltipla e orquestrada
    Separação de dados        Schemas/Tabelas no mesmo banco         | Bancos de dados independentes
    Barreira de entrada       Baixa (Foco no código)                 | Alta (Foco na infraestrutura)
